## 四、P3-11 引入位宽缺陷

```csharp
codes[count++] = (kind << 6) | (group.First.Index & 0x3F);   // kind: 0 / 1 / 2 → 0x00 / 0x40 / 0x80
signature |= (long)(codes[i] & 0x7F) << (i * 7);             // ← 0x80 被 & 0x7F 抹掉
```

- 每槽只有 7 位，但编码占 8 位。
- `kind=2`（`Sequence`）算出的 `0x80|x` 经 `& 0x7F` 后等于 `0x00|x`，**与 `Pair(First=x)` 完全相同**。
- 另：`_ => 2` 的默认分支把 `Sequence` 和 `Other` 合并为同一 kind。

**可达性**：无法构造 14 张牌的互换反例（雀头 X 与顺子 X-Y-Z 共用首张且余牌恰好互补，受张数预算限制），判定为**大概率不可达**，但按构造就是错的。

**修法**（一行）：

```csharp
signature |= (long)(codes[i] & 0xFF) << (i * 8);   // 槽宽 8 位
```

同时把默认分支拆开，`Other` 单独给一个 kind 值。收益远大于风险。
