# 1102工程：推倒胡与小 AI（小报告，2026-11-02）

> 项目代号：**1102工程**（2026-11-02 立项）。本文是该项目的第一份小报告。

## 一、这件事要什么

把七子麻将剥到最原始的判定形态（推倒胡），用它：

1. 记录 AI 的弃牌偏好（数据已有，缺导出与统计）
2. 训练一个本地跑的小 AI，让人机更像真实玩家
3. 验证 AI 的做牌偏好是否符合预期

## 二、已锁定的规则口径

| 项 | 口径 |
|---|---|
| 一般型 | **5 种**：四顺一对、一刻三顺一对、二刻二顺一对、一顺三刻一对、**四刻一对** |
| 七对 | 必须 **7 种不同牌各一对**；四张同牌不能当两对（无龙七对） |
| 十三幺 | 恰好 `19m19p19s1234567z` 这 13 种 + 其中任意一张作对子；**必须门前** |
| 模式 | 关报听、关未听/无役罚符、关庄家 ×1.5、关连庄加分 |
| 计分 | 不记点数，**只记和了 / 流局** |

## 五、LLM 的结论

**实时对局：不可行。**

- 本机 0.6B 模型 CPU 生成约十几秒/次，而一次出牌应 < 1 秒
- 数据量约 70 万条决策，远不够从零训练 LLM；12 GB 显存也只够推理 7B q4

**离线当老师：可行。**

- 用本地小模型对采样局面标注“人类会打哪张”，蒸馏进 1–5M 的 encoder 策略网
- 策略网 CPU 单步 < 1ms，可实时对局

## 六、风险

| 风险 | 说明 |
|---|---|
| 数据偏差 | 现有日志主要是 TieredAi 自己打的，学出来只会更像现有 AI |
| 样本不均衡 | 字牌/终端弃牌多，中张少；需要按场况分层统计 |
| 推倒胡与七子混用 | 两套判定必须隔离，避免 golden 漂移 |
| 小网过拟合 | 参数量小但数据也小，需留出按局切分的验证集 |

## 八、ML 后端选型（2026-11-02 定）

| 层 | 语言 | 理由 |
|---|---|---|
| 数据集导出 | C# | 数据在引擎里，直接读最准 |
| 训练 | Python（`torch 2.9.0+xpu`，吃 Arc B580） | 生态成熟；ML.NET 用不了这块显卡 |
| 评测（A/B 对局） | C# | 必须和引擎同进程真打 |
| 对局内推理 | C# | 玩家机器不装 Python；小模型 CPU 单步 < 1ms |

依赖策略：**先零依赖**（线性/小树 + JSON 权重，C# 手写推理），跑通「数据 → 训练 → 对局」后再升级 ONNX encoder。

## 十一、语料口径（2026-11-02 北极星定）

- **七子的规则来源不单一**：日麻 + 国标 + 部分川麻（未听返杠、暗根/明根），所以语料不能只按一侧规则理解。
- **国标 `final2`**：作为**基准**。牌谱缺场目时，按「谁先起手」定庄：首个摸牌者 = 起手/庄，座次按 `(player − dealer) % 4` 分配东/南/西/北；场风取 `initdata.quan`（缺失记 0）。这些只是概率特征，不要求与真实场目一致。
- **日麻 Tenhou**：作为**人类在不破坏牌效的情况下凑「听牌形」的参考**，不参与七子判役/计分。
- 产出：
  - `dist/dataset/guobiao.jsonl`：12288 局 → 513405 条（`src=guobiao`）
  - `dist/dataset/riichi.jsonl`：1024 局（单个 shard）→ 515152 条（`src=riichi`）
- 转换脚本：`tools/mcr_to_jsonl.py`、`tools/riichi_npz_to_jsonl.py`。
- 注意：日麻样本的 tile 编码是 1..34（legal_tiles），手牌特征是 0..33，脚本已统一到 0..33。
