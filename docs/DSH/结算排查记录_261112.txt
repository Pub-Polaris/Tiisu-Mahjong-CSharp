结算数字排查记录（2026-11-12 凌晨，七子麻将）

一、发生了什么
你打完几局后，结算页的「分数变化」和手算/罚项列表对不上：
- 有两张荒牌流局图：罚项只写了一条「AI 西 未听返杠 −700」，但四家分数变化出现了 ±1400、±2100 这类金额。
- 有一张荣和图：对对和 3 + 缺门 4 + 双碰 2，最终点数 14000，和你按 (7000+1400)×1.5 算的 12600、7000×1.5+1400 算的 11900 都对不上。
- 另外几张图也是同一类现象，都来自 Ursa 版（261112-ee2ccb4）及之前的版本。

二、查出来的两个根因
1) 自摸均摊的余数没有真正收上来
   旧实现是「floor(总点/3) 给三家，余数直接加给自摸者」，但没有任何人付这笔余数。
   结果就是：每自摸一次，牌桌总分悄悄 +1 或 +2。这解释了你说的「最底层的问题」，但它只能解释小额漂移，解释不了几百上千的差。

2) 局内分数变动没有入账，也没有在结算页展示
   一局里除了「流局罚项」，还会有：
   - 拔厄：同一局累计打出 4 张西风后，最后打西的人向其他三家各付 700
   - 报听错和：报听后宣布和牌但赋数不够，按 Z=赋×700 向三家赔付（重罚另有 7000/14000）
   - 双和子跳庄：庄家向子家付 3500
   这些分数变动只改了引擎里的分数，结算页只列「未听返杠 / 无役听牌罚」，所以你看到的就是「罚项一条，分数动了四家」。
   第 4 局那张图可以逐格对上：未听返杠（你庄 +1400、AI南 +700、AI西 −2800、AI北 +700）＋ 拔厄（你付款 −2100、三家各 +700）＝ 你 −700、AI南 +1400、AI西 −2100、AI北 +1400，和截图完全一致。

三、已经做的修改（HEAD 3812f88）
1. 自摸改为按 350 点蓝筹取整
   - 每家付 350 × floor(点数/1050)，除不尽的尾数（0/350/700）不再给胜者。
2. 场供池（底池）
   - 尾数进场供，下一手和牌者拿走；存档持久化；结算页显示「场供 +X」。
3. 局内调整入账
   - 引擎新增 RoundTransfers：拔厄 / 报听错和 / 双和子跳庄 逐笔记账。
   - 结算页（流局第 2 页、和牌页）逐条显示「局内调整 A → B 金额（原因）」。
4. 每局自动自检
   - 和牌局：总分 + 每家分数变化必须能由结算明细 + 场供 + 结算阶段转账解释。
   - 流局：罚项账本 + 局内调整 必须与实际分数逐家一致。
   - 不一致会写 %TEMP%\tiisu-error.log，并在结算页标红。
5. 批量虚拟对局
   - DevTools 新增 --audit-games，用 MatchRuntime 完整命令链路跑，人类座位 AutoPilot。
   - 已跑：1000 场 / 4175 小局 0 问题；2000 场 / 8212 小局 0 问题。
