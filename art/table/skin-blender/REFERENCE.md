# 参考图透视测算（800×600，4:3）

源图：`G:\IGJMJ02\map\map01.bmp`（800×600 RGB，2008-06-05）。原游戏是 2002 年的**预渲染 2D**，
没有 3D 相机参数可查；下面的 25° 只是实验相机取值，**不是**从参考图测出来的确定角度。

## 能可靠量到的

把紫色桌面区域按颜色分割后，取两侧边界做直线拟合：

- 左边界：`x ≈ -1.065·y + 443.3`
- 右边界：`x ≈ 1.024·y + 372.7`
- 两线交点（灭点）：约 `(407, 34)`
- 桌面顶边：约 `y = 232`
- 侧边在画面中的斜率：约 `46.8°`（相对水平线）

这些只依赖像素，不依赖 FOV。

## 为什么不能反推 3D 角度

画面是预渲染的，没有相机元数据。俯角必须由「灭点到画面中心的距离 ÷ 焦距」反推，
而焦距来自未知的视场角。同一个灭点可以对应多个俯角：

| 假设 | 焦距 | 俯视角 |
|---|---:|---:|
| 垂直 FOV 55° | 576px | **24.8°** |
| 垂直 FOV 50° | 643px | 22.5° |
| 水平 FOV 60°（垂直 46.8°） | 691px | 21.1° |

所以 25° 只能作为**本实验的相机选择**，不能称为参考图的角度。

## 当前实现

- `Soft3DTable`：实验相机固定 25° / 垂直 FOV 55°，只为验证「桌面 Soft-3D 只烘一次」。
- `render_4x3_reference.py`：在同一假设下出 4:3 对照图。
- 若要 1:1 复刻参考图，应直接用**消失点/四条边做 2D 投影贴图**，不要再反推 3D FOV。

## 复现

```powershell
blender --background Assets\Table.blend --python art\table\skin-blender\render_4x3_reference.py
```

输出 `preview-4x3.png`；`Soft3DTable` 使用 `CameraPitchDegrees = 25f`、`CameraFovDegrees = 55f`。
